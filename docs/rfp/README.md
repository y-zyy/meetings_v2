# 외주개발 상세요구사항정의서

`KAI_Meetings_외주개발_상세요구사항정의서.docx`는 현재 리포지토리(backend + service/frontend)의
코드를 기반으로 작성한 As-Is 분석과, 웹 서비스 UI/UX·백엔드 고도화를 외주 개발사에 위탁하기 위한
상세 요구사항을 정리한 문서다.

## 구성

- 0장: 문서 개요 및 용어 정의
- 1장: 프로젝트 개요 및 외주 목적
- 2~6장: As-Is 분석 (아키텍처/인프라, DB 설계, API 명세, 화면 구성, 비기능 현황)
- 7장: As-Is 분석에서 발견된 이슈 및 기술부채 목록 (착수 전 발주사-개발사 협의 필요)
- 8~10장: UI/UX·백엔드 고도화 요구사항 및 To-Be 비기능 요구사항
- 11~13장: 산출물, 제안요청 사항, 기타 유의사항(보안/방위산업 특성)

## 작성 기준

2026-08-10 기준 `main` 브랜치 소스코드(backend/, service/frontend/web_service.html, infra/)를
직접 분석하여 작성했다. 실제 발주 시점 코드와 차이가 있을 수 있으므로 최종 확인이 필요하다.

## 요구사항 표기 규칙 (v1.1~)

0.1(문서 목적)/1.2(외주 목적)/7장(이슈 조치)/8~13장(요구사항·산출물·제안요청·유의사항)의
개별 항목은 `REQ-영역-일련번호` 형식의 고유 식별자를 가지며, 모두 "~해야 한다"로 종결되는
필수 이행사항으로 기술되어 있다. 2~6장(As-Is 현황)은 현재 상태에 대한 사실 서술이므로
동일한 형식을 적용하지 않았다.

| 접두어 | 영역 | 위치 |
|---|---|---|
| REQ-UX-### | UI/UX 요구사항 | 8장 |
| REQ-BE-### | 백엔드 요구사항 | 9장 |
| REQ-NFR-### | 비기능 요구사항(To-Be) | 10장 |
| REQ-DEL-### | 산출물 | 11장 |
| REQ-PROP-### | 제안서 포함 사항 | 12장 |

7장 "As-Is 이슈 및 기술부채" 표의 "조치 요구사항" 열은 위 REQ-ID를 인용하여 8~9장과
상호 추적 가능하도록 연결되어 있다.
